## ARCHITECTURE DECISIONS

### Why Cluster-Specific Directories?
- Each cluster has different network configurations (IPs, VLANs, domains)
- Allows independent management of different datacenters
- Scales to support additional clusters (man1, sfo1, etc.)
- Clear separation prevents accidental cross-cluster deployments

### Why Both charts/ and manifests/?
- Legacy: applications originally referenced `path: charts/`
- Current: new structure uses `path: manifests/`
- Both exist for compatibility during migration
- Eventually will consolidate to single directory

### Why SSH Authentication for Git?
- More secure than HTTPS with tokens
- Consistent with existing pdx2 setup
- Private key managed in Kubernetes secret
- Bitbucket SSH key format: `git@bitbucket.org:noctel-bitbucket/noctel-gitops.git`

### Why Separate Config Files per Cluster?
- Different IP ranges and network configs
- Different domain names (pdx1-dev.telnoc.com vs pdx2-dev.telnoc.com)
- Different resource allocations
- Allows cluster-specific customization

## HELM CHART STRUCTURE

Each service has a Helm chart in manifests/ with standard structure:
```
manifests/service-name/
├── Chart.yaml           # Chart metadata and dependencies
├── values.yaml          # Default values (usually empty or minimal)
└── templates/
    ├── deployment.yaml  # Kubernetes Deployment
    ├── service.yaml     # Kubernetes Service
    ├── ingress.yaml     # Traefik IngressRoute
    └── configmap.yaml   # ConfigMap (if needed)
```

Values are provided via cluster-specific config files (e.g., pdx1-dev-config.yaml).

## METALLB CONFIGURATION

MetalLB requires:
1. IP address pools per environment
2. L2 advertisements with VLAN interface mappings

Example (pdx2-metallb-config.yaml):
```yaml
namespace: metallb-system

ipAddressPools:
  - name: dev-vlan-pool
    addresses:
      - "10.0.97.20-10.0.97.30"
    autoAssign: true

  - name: qa-vlan-pool
    addresses:
      - "10.0.98.20-10.0.98.30"
    autoAssign: true

  - name: prod-vlan-pool
    addresses:
      - "10.0.99.20-10.0.99.30"
    autoAssign: true

l2Advertisements:
  - name: dev-vlan-advertisement
    ipAddressPools:
      - dev-vlan-pool
    interfaces:
      - bond0.677  # Dev VLAN interface

  - name: qa-vlan-advertisement
    ipAddressPools:
      - qa-vlan-pool
    interfaces:
      - bond0.678  # QA VLAN interface
```

For pdx1, similar structure needed but with pdx1-specific IPs and interfaces.

## GITOPS WORKFLOW

1. **Make Changes**: Edit files in local repository
2. **Test Rendering**: Use `helm template` to verify changes
3. **Commit**: `git add` and `git commit` with clear message
4. **Push**: `git push origin main`
5. **Wait or Force Sync**: ArgoCD syncs every 3 minutes, or force via UI
6. **Monitor**: Check ArgoCD UI for sync status and errors
7. **Verify**: Check pods/services are running correctly
8. **Rollback if Needed**: `git revert` and push
